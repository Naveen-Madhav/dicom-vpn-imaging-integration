========================================================================================================================
                               NAT TRAVERSAL (NAT-T) ADDITIONAL OVERHEAD (IF APPLICABLE)
========================================================================================================================
When NAT Traversal is active (UDP Port 4500):
- An 8-byte UDP header is inserted between the Outer IP Header and the ESP Header.
- Outer IP (20B) + UDP 4500 (8B) + ESP (8B) + IV (8B) + Payload + Pad (2B) + PadLen/NextHdr (2B) + ICV (16B)
- Total encapsulation overhead increases to ~64 - 74 bytes.
- Inner TCP MSS must be clamped to <= 1360 bytes.

========================================================================================================================
                                 WHAT HAPPENS IN A PATH MTU (PMTU) BLACKHOLE?
========================================================================================================================
1. Modality negotiates TCP session with PACS. SYN packet is 60 bytes (well below MTU). Connection establishes cleanly.
2. Modality sends DICOM A-ASSOCIATE-RQ (approx 250 bytes). PACS responds A-ASSOCIATE-AC. Association accepted!
3. Modality executes C-ECHO-RQ (approx 120 bytes). PACS responds C-ECHO-RSP. C-ECHO test passes!
4. Modality starts C-STORE-RQ with high-resolution CT study. Modality's TCP stack segments the image data into full-sized
   packets with TCP payload = 1460 bytes (DF bit set = 1). Total packet size = 1500 bytes.
5. Edge VPN Gateway attempts to encapsulate 1500-byte inner packet into ESP. Total outer size = 1564 bytes.
6. The physical WAN interface MTU is 1500 bytes. The packet exceeds MTU.
7. Because DF (Don't Fragment) bit is set, the gateway drops the packet.
8. If ICMP Type 3 Code 4 ("Destination Unreachable, Fragmentation Needed and DF Set") is blocked by firewalls, the Modality
   never learns that the packet was too large.
9. SYMPTOM: C-ECHO always succeeds. C-STORE hangs indefinitely, eventually timing out with a broken TCP pipe!
10. SOLUTION: Enforce TCP MSS Clamping on the VPN gateways:
    iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu
    or:
    iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --set-mss 1360
